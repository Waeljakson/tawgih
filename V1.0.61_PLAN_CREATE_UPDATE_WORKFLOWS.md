# V1.0.61 — Plan create/update workflows

- First save calls `guidance_save_plan`.
- Later saves for the same Grade + School + Department + AcademicYear + Term call `guidance_update_plan`.
- The frontend does not require the user to handle Bubble IDs manually.
- A local identity marker is stored after a confirmed create so repeated saves do not create duplicate rows even when `guidance_save_plan` returns only `success` and `message`.
- Loading plan rows from Bubble seeds the same identity marker.
- If the plan identity changes (for example a different term), it is treated as a different plan and uses the create workflow.
