# V1.0.52 — Direct School Manager Lookup

## Root cause
Previous versions depended on the general employee directory (`Users Data`) being available after `guidance_bootstrap`. If Bubble privacy/API scope did not return the school manager in that general directory, no frontend role-matching rule could find the manager.

## Fix
- Resolves the `job_titels` record for `مدير المدرسة`, `مديرة المدرسة`, `مدير مدرسة`, or `مديرة مدرسة`.
- Queries `Users Data` directly with `Current Job = <school-manager job id>`.
- First tries a server-side school intersection using `Schools contains <current school id>` and `activity schools contains <current school id>`.
- Falls back to fetching manager-role rows only and intersects their school relations locally.
- Accepts a manager returned directly by `guidance_bootstrap`, Current Users Data, or the School thing as first priority.
- Caches the resolved manager per current school scope in sessionStorage and reapplies it on every page.
- Clears the manager cache on login/logout.
- Dispatches `mishkat:school-context-changed` after asynchronous resolution so plans/reports/UI update immediately.

## Verification
A simulated Bubble response with no employees in `guidance_bootstrap` was tested. The direct Data API lookup resolved `مدير المدرسة`, fetched the matching Users Data row, matched the current School, and populated `managerName` successfully.
